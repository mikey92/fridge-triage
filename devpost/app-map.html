Fridge Triage — App Map

A snapshot of how the app is put together, made from commit 18bd476. The code can drift from this map; the file paths and names below are the place to start looking.

What it is, in four pieces

After a power outage, you photograph your fridge and freezer and get Toss, Check, Refreeze or Keep for each item, decided by the FoodSafety.gov power-outage charts.

  • The chart (src/chart.ts): both FoodSafety.gov charts as data, word for word.
  • The rules (src/rules.ts): turn a chart row and the outage facts into a verdict. No AI here.
  • The recognizer (worker/recognize.ts): the only server code. Sends a photo to a vision model, which names the food and picks a chart row.
  • The page (src/App.tsx and src/components/): the cold clock, the photo slots, the item list with fixes, the verdicts and the loss record. State is saved on the device by src/store.ts.

One action, followed through the code

“Add a photo of the fridge and see the shredded cheese tossed and the cheddar kept.”

A three-stop route (reference)

A reference route through the part that decides; it was not walked through live.

  1. src/chart.ts — search for "r-shredded-cheese" and "r-hard-cheese".
    Two rows from the refrigerated chart: “Shredded cheeses” with the rule "discard", and “Hard cheeses: Cheddar, Colby, Swiss, Parmesan, provolone, Romano” with "keep". The model only ever returns one of these ids.
  2. src/rules.ts — verdict(), then fridgeVerdict().
    verdict() finds the item's row (following cut/opened partners in effectiveRow()) and the outage length. fridgeVerdict() keeps everything for the first 4 hours with the door closed (FRIDGE_HOURS_DOOR_CLOSED), then reads the row's rule: "discard" becomes Toss.
  3. src/components/Verdicts.tsx — VerdictLine.
    Shows the item's name, the reason from the rule, and the chart row it came from. The “Fix” button opens ItemEditor, and any change re-runs verdict().

A practice to reuse

Let the model recognize; let a vetted table decide. The model's answer is only an index into src/chart.ts: cleanItems() in worker/recognize.ts drops any row id that isn't in the chart, and an item without a row is always Check, never Keep. Because the decision is a pure function over a fixed table, tests/rules.test.ts can check every row of both charts in both columns.

On another project where an AI's output drives a decision with real consequences (prices, eligibility, safety), the same shape works: ask the model for a choice from a closed list, validate it, and keep the decision in code you can test exhaustively.

Run it again

npm install, then npm run dev and open http://localhost:5173. npm test runs the rule, clock, storage and recognizer checks; npm run e2e runs the whole journey in Chrome. Photo recognition needs RELAY_URL and RELAY_KEY in .dev.vars (see .dev.vars.example); without them the app runs in manual mode.
